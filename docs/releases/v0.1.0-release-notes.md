## What 0.1.0 contains

A self-hosted deployment can authenticate users, select an organization, inventory assets, upload CycloneDX JSON SBOMs, and persist the parsed graph. CISA KEV synchronization can run when an operator enables it. Sanitized provider status is available. Production OSV acquisition stays disabled.

Owners can record Product Match Evidence for one approved local npm revision and can create a Finding from qualifying evidence. Owners and admins can inspect a Finding, read its latest observation, calculate priority, and read the controlled remediation queue after an operator publishes the admitted builtin in that deployment. Owners can append a priority review. A review does not change queue order.

Owners and admins can export that queue as JSON or CSV from `POST /remediation-queue/export` and from `/remediation-queue`. The export cap is 150 Findings. The export does not calculate priority. One `export.created` audit row records the response SHA-256 and byte length. The file bytes are not stored.

## What 0.1.0 does not contain

- A shared or production deployment. The built-in priority policy must still be published explicitly in each deployment.
- automatic Finding creation, matching, or priority recalculation
- Finding lifecycle transitions, assignments, remediation tasks, or verification
- task, acceptance, or observation exports
- a generic Finding list
- GitHub or other source-control integrations
- a claim of compliance, certification, exploitability, or completed remediation

## Operator notes

Publication of builtin `patchpilot.builtin.v0` version 2 remains the deployment-local command `pnpm publish-builtin-priority-policy`. A repository merge does not publish that row. Until it exists, priority calculation, priority read, the queue, and the export return 503.

# Architecture

Current checkpoint: [docs/project/current-state.md](../project/current-state.md).

This directory is the v0.1 architecture design for PatchPilot. Sessions 3–4 scaffolded application shells, CI, and governance. Session 5 adds the PostgreSQL tenant schema and persistence adapters. Session 6 implements local-password authentication. Session 7 persists asset inventory. Session 8 implements CycloneDX JSON upload, private object storage, outbox relay, worker-thread parse, and graph persistence ([ADR 0020](../adr/0020-sbom-ingestion-graph-completion.md)). Session 9 Batch 1B records [ADR 0021](../adr/0021-vulnerability-intelligence-import-foundation.md) (import-only shared catalog). Subsequent Session 9 batches implement KEV import runtime: restricted CISA HTTPS and private snapshot storage, isolated parsing, crash-safe synchronization, the worker scheduler/processor/retry reconciler, and authenticated sanitized provider-status GETs ([ADR 0022](../adr/0022-intelligence-provider-status-authorization.md)). Session 10 adds canonical CVE identity persistence and read-only active-catalog KEV membership derivation ([ADR 0023](../adr/0023-provider-neutral-cve-identity.md)). Session 11 Batch 1B accepts [ADR 0024](../adr/0024-authoritative-affected-version-source-and-osv-acquisition.md): OSV is the future affected-version authority and instance-owned catalog acquisition is the approved direction. Session 11 Batch 1C accepts [ADR 0025](../adr/0025-ecosystem-aware-package-identity-and-version-evaluation.md): ecosystem-aware package identity and fail-closed evaluation architecture. Session 11 Batch 1D accepts [ADR 0026](../adr/0026-authoritative-match-evidence-and-finding-lifecycle.md): Finding natural key, append-only match evidence, observation semantics, and the Finding-write gate. Session 12 implements the disabled, uncomposed OSV runtime-enablement foundation (listing, pagination, durable coordination, halt, and bounded observability) behind [ADR 0028](../adr/0028-osv-runtime-enablement-architecture-and-safety.md). Production OSV remains disabled. Session 13 Batch 1-R accepts [ADR 0029](../adr/0029-first-real-provider-osv-canary-authorization-and-safety.md) canary architecture without provider contact. Session 13 Batch 2A defines framework-independent canary operator-identity and authorization contracts. Session 13 Batch 2B adds schema-only persistence without adapters or execution. Session 13 Batch 2B-R independently reviewed and froze that schema. Session 13 Batch 2C implements uncomposed PostgreSQL authorization adapters without authentication, CLI, canary execution, or provider contact. Session 13 Batch 2C-R independently reviewed those adapters. Acceptance authorizes only later operational-control implementation. Session 14 Batch 1 proposes [ADR 0030](../adr/0030-first-ecosystem-matching-architecture.md) and [ecosystem matching](ecosystem-matching.md). Session 14 Batch 2 implements the uncomposed in-memory npm evaluator. Session 14 Batch 2-R reviewed that evaluator. Session 14 Batch 3 persists immutable match-evaluation evidence and does not write Findings. Session 15 Batch 1 proposes [ADR 0031](../adr/0031-product-evidence-provenance-architecture.md) and [product-evidence provenance](product-evidence-provenance.md). Synthetic match-evaluation evidence persistence is implemented, immutable, and production uncomposed. Immutable advisory revisions and Vulnerability bindings are implemented and production uncomposed. Owner `POST /assets/:assetId/product-match-evaluations` can write Product Match Evidence for one approved revision. Product-evidence eligibility composition still stores no eligible record. Product-evidence eligibility composition is implemented and production uncomposed. It produces no eligible record, invokes no product evaluator in the accepted zero-eligibility state, and writes no product match row. ZIP processing remains unavailable. Automatic Finding creation remains unavailable. Owner POST /findings is composed in the API process.

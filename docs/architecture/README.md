# Architecture

Current checkpoint: [docs/project/current-state.md](../project/current-state.md).

This directory is the v0.1 architecture design for PatchPilot. Sessions 3–4 scaffolded application shells, CI, and governance. Session 5 adds the PostgreSQL tenant schema and persistence adapters. Session 6 implements local-password authentication. Session 7 persists asset inventory. Session 8 implements CycloneDX JSON upload, private object storage, outbox relay, worker-thread parse, and graph persistence ([ADR 0020](../adr/0020-sbom-ingestion-graph-completion.md)). Session 9 Batch 1B records [ADR 0021](../adr/0021-vulnerability-intelligence-import-foundation.md) (import-only shared catalog). Subsequent Session 9 batches implement KEV import runtime: restricted CISA HTTPS and private snapshot storage, isolated parsing, crash-safe synchronization, the worker scheduler/processor/retry reconciler, and authenticated sanitized provider-status GETs ([ADR 0022](../adr/0022-intelligence-provider-status-authorization.md)). Session 10 adds canonical CVE identity persistence and read-only active-catalog KEV membership derivation ([ADR 0023](../adr/0023-provider-neutral-cve-identity.md)). Session 11 Batch 1B accepts [ADR 0024](../adr/0024-authoritative-affected-version-source-and-osv-acquisition.md): OSV is the future affected-version authority and instance-owned catalog acquisition is the approved direction. Session 11 Batch 1C accepts [ADR 0025](../adr/0025-ecosystem-aware-package-identity-and-version-evaluation.md): ecosystem-aware package identity and fail-closed evaluation architecture. Session 11 Batch 1D accepts [ADR 0026](../adr/0026-authoritative-match-evidence-and-finding-lifecycle.md): Finding natural key, append-only match evidence, observation semantics, and the Finding-write gate. Session 12 implements the disabled, uncomposed OSV runtime-enablement foundation (listing, pagination, durable coordination, halt, and bounded observability) behind [ADR 0028](../adr/0028-osv-runtime-enablement-architecture-and-safety.md). Production OSV remains disabled. Session 13 Batch 1-R accepts [ADR 0029](../adr/0029-first-real-provider-osv-canary-authorization-and-safety.md) canary architecture without provider contact. Session 13 Batch 2A defines framework-independent canary operator-identity and authorization contracts. Session 13 Batch 2B adds schema-only persistence without adapters or execution. Session 13 Batch 2B-R independently reviewed and froze that schema. Session 13 Batch 2C implements uncomposed PostgreSQL authorization adapters without authentication, CLI, canary execution, or provider contact. Session 13 Batch 2C-R independently reviewed those adapters. Acceptance authorizes only later operational-control implementation. Session 14 Batch 1 proposes [ADR 0030](../adr/0030-first-ecosystem-matching-architecture.md) and [ecosystem matching](ecosystem-matching.md). Session 14 Batch 2 implements the uncomposed in-memory npm evaluator. Session 14 Batch 2-R reviewed that evaluator. Session 14 Batch 3 persists immutable match-evaluation evidence and does not write Findings. Session 15 Batch 1 proposes [ADR 0031](../adr/0031-product-evidence-provenance-architecture.md) and [product-evidence provenance](product-evidence-provenance.md). Synthetic match-evaluation evidence persistence is implemented, immutable, and production uncomposed. Immutable advisory revisions and Vulnerability bindings are implemented and production uncomposed. Real product-eligible match evidence is unavailable. Product-evidence eligibility composition is implemented and production uncomposed. It produces no eligible record, invokes no product evaluator in the accepted zero-eligibility state, and writes no product match row. ZIP processing and Finding creation remain unavailable.

Decisions in this directory follow the Architecture Decision Records under [docs/adr/](../adr/README.md). ADRs 0001–0026, 0028–0029, and 0032–0035 are **Accepted**. [ADR 0032](../adr/0032-maintainer-reviewed-advisory-authority.md) is production uncomposed. [ADR 0035](../adr/0035-controlled-finding-creation.md) is creation-only architecture. Session 1 implements its contracts and process-local authorization. The atomic creation transaction is implemented and production uncomposed. Tenant-facing inspection is not implemented. Lifecycle transitions remain unavailable. [ADR 0027](../adr/0027-osv-acquisition-persistence-and-catalog-activation.md), [ADR 0030](../adr/0030-first-ecosystem-matching-architecture.md), and [ADR 0031](../adr/0031-product-evidence-provenance-architecture.md) remain **Proposed**. Remaining gaps are listed in [open-decisions.md](open-decisions.md). OD-1, OD-2, and OD-3 are closed by [ADR 0019](../adr/0019-local-password-sessions.md). Session 8 ingestion completion is closed by [ADR 0020](../adr/0020-sbom-ingestion-graph-completion.md). Session 9 import-only catalog access is closed by [ADR 0021](../adr/0021-vulnerability-intelligence-import-foundation.md). Sanitized provider-status authorization is closed by [ADR 0022](../adr/0022-intelligence-provider-status-authorization.md). Canonical CVE identity is closed by [ADR 0023](../adr/0023-provider-neutral-cve-identity.md) for identity tables, persistence adapters, and read-only active-catalog membership; Finding enrichment, risk, APIs, workers, and fan-out do not exist. OSV affected-version authority and instance-owned acquisition direction are closed by [ADR 0024](../adr/0024-authoritative-affected-version-source-and-osv-acquisition.md); exact object/listing transport, ZIP, matching, and Finding writes remain later. Package identity and fail-closed evaluation architecture are closed by [ADR 0025](../adr/0025-ecosystem-aware-package-identity-and-version-evaluation.md). The active registries that admit product eligibility are empty. Session 14 implements one uncomposed npm evaluator and immutable synthetic match-evaluation persistence. Session 15 persists immutable advisory revisions and reviewed Vulnerability bindings, and composes provider-free eligibility without returning `eligible`, invoking the product evaluator, or writing a product match row. Finding identity, match evidence, observation semantics, and the Finding-write gate are closed as architecture by [ADR 0026](../adr/0026-authoritative-match-evidence-and-finding-lifecycle.md). [ADR 0035](../adr/0035-controlled-finding-creation.md) admits one creation-only slice. Session 1 implements its contracts and process-local authorization. The atomic creation transaction is implemented and production uncomposed. Tenant-facing inspection is not implemented. Lifecycle transitions remain unavailable. The Finding schema is placeholder infrastructure. Finding creation, production matching, and risk scoring are unavailable. Session 11, Session 12, and Session 13 Batch 2C-R remain zero-Finding. [ADR 0010](../adr/0010-osv-correlation.md) remains future correlation. OD-14 is unchanged.

## What this design set does not claim

- Product workflows for scoring and remediation are specified here and are not operational. Authentication, asset inventory, Session 8 upload-to-graph, and Session 9 KEV import plus sanitized provider-status APIs are production composed. Session 10 canonical CVE identities and active-catalog membership derivation exist and are production uncomposed. Session 12 implements the OSV runtime-enablement foundation and leaves it production uncomposed. Production OSV acquisition remains disabled. Session 14 implements one uncomposed npm evaluator and immutable synthetic match evidence. Session 15 persists immutable advisory revisions and composes eligibility without storing a product-eligible evaluation. Product Match Evidence is implemented and production uncomposed. The provider-free product-evidence path is implemented and verified in disposable PostgreSQL. Persistent product-eligible evaluation count: 0. Real product-eligible evaluation count remains 0. Product-evidence eligibility composition is not product matching. Automatic matching is not operational. No ZIP processing or Finding creation exists. Finding enrichment, risk, dashboards, and manual sync remain later.
- The foundation does not claim SOC 2, ISO 27001, FedRAMP, PCI, HIPAA, or any other compliance status.
